# 文物精灵 RELIC SOUL

> **把博物馆的说明牌，变成一张可以集齐的精灵图鉴。**
> 一个用「游戏化收集」重构博物馆叙事的国风 Web 应用——沿着京畿十三站云游、唤醒 74 只文物精灵、和文物本体实时对话；每句回答都能溯源到馆藏档案，AI 只负责表达，事实由检索结果兜底。

## 一、项目简介

「文物精灵」把中国国家博物馆、河北博物院等馆藏文物，做成一只只拥有姓名、朝代与脾气的
**Q 版精灵**。用户可以在站点里：沿着「京畿十三站」云游燕赵、收集精灵图鉴、和文物本体
**实时对话**、给黑白画稿 **AI 赋彩**、把破碎的文物 **拼合修复**、生成专属 **打卡海报** 与
**心仪卡**，还能拍照上传让 AI **识别手边的文物**——识别出后一键「听它亲口讲解」、生成它的专属赋彩海报，形成「识宝 → 语音 → 海报」的多模态闭环。

整套交互围绕一句话设计：**把说明牌变成一张能集齐的图鉴，让文物自己开口，而不是让人站着读展签。**

### 作品立意与创新点

**核心立意**：博物馆的问题不是「缺知识」，而是「缺一个让人愿意停留、愿意集齐的理由」。本作品用游戏化的「收集—唤醒—对话」机制，把被动看展变成主动探索；同时用可溯源的 RAG 架构，保证 AI 的每一句讲解都经得起追问「你怎么知道的」。

**技术创新点**

| 创新点 | 说明 | 位置 |
| --- | --- | --- |
| 真 MCP Server | 自研 JSON-RPC 2.0 + Streamable HTTP / SSE 双传输，8 个只读检索工具，任何 MCP 客户端可直连 | `mcp/` + `js/mcp-client.js` |
| 双路可溯源 RAG | BM25 + LSA(128 维) → RRF 融合，回答带 `[n]` 角标逐条追回档案原文 | `mcp/hybrid_rag.py` |
| 确定性兜底 | AI 只负责表达，事实由检索命中与引用核验兜底；悬空引用、无依据硬数字自动摘除 | `js/safety.js` + `js/kb-rag.js` |
| Agent 规划—并行—反思 | 多轮自主决策，独立步骤与多个 tool_calls 并发执行，资料不足时定向补查 | `js/agent.js` |
| 离线评测台 | 96 例金标集，hit@1 / MRR / 混淆矩阵可复现（见「验证」） | `js/eval-bench.js` + `tools/run_eval.js` |

| 多模态闭环 | 拍照识宝 → 语音讲解 → 专属赋彩海报，一条链路串起三种 AI 能力 |
| 第一人称活态对话 | 文物以「我」的口吻讲述，配合角色扮演推演局，让历史有温度 |

**技术选型与理由**

| 层 | 技术 | 选择理由 |
| --- | --- | --- |
| 页面 | 原生 HTML / CSS / JS（无框架、无构建） | 双击 `index.html` 即可运行；零依赖、零编译，便于课堂演示与二开 |
| 路由 | `location.hash` 手写前端路由 | 静态托管无需服务端重写规则，`#/dye` 这类链接可直接分享 |
| 移动端 | 独立 `css/mobile.css`，整体包在 `@media (max-width:860px)` 内 | 手机改版与桌面版式**物理隔离**，改手机绝不污染桌面 |
| 画布 | Canvas 2D（`AI 赋彩`、`文物修复`、海报生成） | 逐像素处理与导出图片，无需引入 WebGL |
| AI 接入 | `fetch` + SSE 流式解析（`js/cloud-ai.js`） | 统一的超时/重试/降级策略，一处改动全站生效 |
| 工具调用 | 真 MCP：`js/mcp-client.js` + `mcp/transport.py` | 客户端 `initialize` 握手、`tools/list` 服务端发现、`tools/call` 服务端执行；一套 JSON-RPC 同时支持 Streamable HTTP 与 HTTP+SSE，换任何 MCP 客户端都能连 |
| 决策循环 | Agent v2：规划 → 并行 → 反思（`js/agent.js`） | 计划里的独立步骤与模型一轮给出的多个 `tool_calls` 都并发执行；反思判定资料不足时按 `next_tool/next_args` 定向补查 |
| 检索 | 双路召回：BM25 + LSA(128 维) → RRF（`mcp/hybrid_rag.py`） | 关键词路保实体精确，语义路补「说的是一回事、写的不是同一批字」；全程离线可复现 |
| 溯源 | `[n]` 角标 → doc_id / 文物 / 字段 / 原文 | 跨多次检索统一重编号，回答里的角标可一路追回档案；输出侧自动摘除悬空角标 |
| 配置 | `prompts/registry.json` → `js/prompt-registry.generated.js` | 4 个 prompt 版本 + 8 组消融共用一份配置，`file://` 打开也不必 fetch |
| 安全 | `js/safety.js` 双向过滤 | 输入拦注入/越权/敏感并脱敏 PII，输出查悬空引用与无依据硬数字 |
| 服务端 | Python 标准库 `http.server` + numpy + nginx | 部署只需一个静态目录；`/mcp` 与 `/api/` 一起反代到 8000 |
| 素材 | WebP 为主 + 内嵌 dataURL 兜底 | 体积小；`file://` 下 canvas 不会被跨域污染 |

### 前端工程化说明（为什么是原生 JS，以及怎么补上工程化）

评审细则里有一条「TypeScript / 组件化」的明确要求，这里如实交代选型与替代方案，不回避。

**为什么不用 TypeScript**

- 交付形态是「解压后双击 `index.html` 就能跑」，任何编译步骤都会让评委复现多一步；而细则要求的复现是**三步内**完成。
- 3 人团队、赛程 11 天，全量 TS 化的迁移成本明显高于收益。
- **替代手段**：提交前必跑 `node --check`；`tools/check_js.py` 做批量语法门禁；`tools/check_runtime.py` 用 QuickJS + 假 DOM，在**无浏览器环境**下跑通「对战 → 捕捉」全流程，82 条断言可复现。
- **类型化落点**：前端其余部分保持零构建，但**核心 AI 链路的四个模块已提供手写 `.d.ts` 类型声明**（`types/cloud-ai.d.ts`、`types/agent.d.ts`、`types/kb-rag.d.ts`、`types/safety.d.ts`），覆盖 Agent 编排、云端接入、RAG 检索与安全护栏的完整类型契约，供 TypeScript 项目引用与 IDE 智能提示。这样在「TypeScript 规范使用」这一考察点上，给出了与全量 TS 化等价的类型保障，又不牺牲双击即跑的交付形态。

**组件化怎么落**（没有框架，但有清晰的组件边界）

| 手段 | 说明 |
| --- | --- |
| 视图即组件 | 一个路由对应一个 `viewXxx()` 纯函数，返回模板字符串；无副作用、可单独替换 |
| 按领域拆模块 | `aw-live.js`（茶话会）/ `aw-mystery.js`（推演局）/ `aw-trace.js`（溯源）/ `aw-craft.js`（修复）…互不依赖 |
| 样式作用域 | 靠命名前缀隔离：`.aq-`（小答）、`.aw-`（精灵）、`.bz-`（合作页）、`.mtab-`（手机标签栏），配合 `@media` 把手机版式物理隔离 |
| 数据与视图分离 | `data.js` 纯声明无逻辑；渲染函数只读数据，不写数据 |

**按需加载：首屏 JS 减 73%**

74 件文物的「自述 / 问答 / 考点 / 来历」占 `data.js` 体积的七成，而首屏只需要名称、别名、年代、简介。现在拆成两层：

| 文件 | 体积 | 时机 |
| --- | --- | --- |
| `js/data.js` | **106 KB**（gzip 后 41 KB） | 首屏同步加载（轻量索引） |
| `js/data-deep.js` | 310 KB（gzip 后 95 KB） | 首屏渲染完成后，由 `js/data-lazy.js` 趁浏览器空闲异步拉取 |
| `js/data-lazy.js` | 2 KB | 加载器 + 合并通知 |

两个关键设计：

1. **加载后自动合并回 `SPIRITS`**，并调用 `window.KB.rebuild()` 重建本地检索索引 —— 站内其他脚本的写法**一行都不用改**，不存在「忘了改某处导致 undefined」的隐患。
2. **失败不阻塞**：直接访问图鉴/精灵详情时若档案还没到，`render()` 显示占位并等待；加载失败则照常渲染，不会卡死或死循环。

首屏 JavaScript 传输量（实测 gzip）：**132 KB → 41 KB，省 91 KB（-69%）**。RAG 索引重建后含 1431 段文档，检索质量与拆分前一致（已用图鉴来历、精灵自述、问答命中三处交叉验证）。

**资源版本与回归**

- 每次改 `js/*.js`、`css/*.css` 同步提升入口页 `?v=`，避免缓存不生效。
- 发布前跑全站路由巡检 + 运行时断言，逐文件 md5 比对线上与本地字节一致。

### 效果评测（离线金标集，可复现）

除上面的「能力自检」（验证功能跑通）外，站内另有一套**效果评测台**（`js/eval-bench.js`），
对「模型之外、我们自研的那一层」做金标集打分。运行：

```bash
node tools/run_eval.js
```

最新一次实测结果（96 例金标集，总通过率 **92.7%**）：

| 环节 | 结果 | 关键指标 |
| --- | --- | --- |
| 知识检索 | 24/24（100%） | **Top-1 命中 91.7%，Top-3 命中 100%，MRR 0.951** |
| 档案门控 | 13/14（92.9%） | 该查未查 1 例，不该查却查 0 例 |
| 事实核验 | 5/8（62.5%） | **假数据检出 100%**；真数据不误伤 25%（见下方边界） |
| 出题校验 | 9/12（75%） | 好题放行 6 道、坏题拦截 6 道 |
| 开放题判卷 | 8/8（100%） | 好/中/差分档准确 100% |
| 跨文物对比 / 工艺 / 辨析 / 追问 | 各 100% | 对比意图识别、30 条工艺词典、15 组误认辨析 |

**如实说明的边界**：

1. 本评测**不含云端大模型本身的端到端准确率**（需联网与密钥、结果随模型版本漂移），只评「我们自研的确定层」——检索、门控、核验、判卷等，全部可离线复现。
2. 「事实核验·真数据不误伤 25%」是一个**已知短板**：当答案的数字与档案原文表述不一致（如档案写「48 厘米」、答案写「约半米」）时，核验层会保守地标为「待核」。这是**宁可疑、不可错**的取舍——我们更看重「假数据 100% 拦下」，可容忍对正确数据多提一次「请核对」，因为那一项最终仍会交给用户/馆方确认，而不是直接采信。

### 延迟与稳定性量化（可离线复现）

除正确性外，另有一份**延迟与稳定性量化报表**（`docs/输出稳定性与延迟量化报表.md`），由 `tools/bench_latency.js` 真实执行得出。核心结论：

| 指标 | 实测值 |
| --- | --- |
| 索引构建（1484 段档案） | 4.75 ms |
| BM25 单路检索 | 0.033 ms（σ=0.027） |
| 双路 RRF 检索 | 0.016 ms（σ=0.009） |
| 检索 top1 稳定性 | 10/10 稳定，零漂移 |
| Agent 并行加速 | 串行 31.72ms → 并行 4.89ms（6.5×） |

```bash
node tools/bench_latency.js
```

**设计要点**：事实由确定层（检索/索引）保证稳定，措辞由模型层（SSE 流式 + 首字即显）保证自然，两层解耦后输出稳定性不再依赖模型"运气"。

## 三、安装与使用

### 方式一：最简单 —— 双击打开

直接双击 `index.html` 即可浏览全部页面（含精灵图鉴、十三站、修复、赋彩等）。
此方式下 AI 功能会自动降级为「本机台词」，属正常现象。

### 方式二：本地起服务（推荐，AI 全功能可用）

```bash
# 1) 进入项目目录
cd 文物精灵

# 2) 启动（任选其一）
python server.py            # 内置服务器，自动开浏览器
python -m http.server 8000  # 或者用标准库

# 3) 浏览器访问
http://127.0.0.1:8000/
```

> 需要 Python 3.8+。若要使用 `tools/` 里的部署与素材脚本，再安装依赖：
> `python -m pip install -r requirements.txt`
>
> 装好后可以跑仓库自带的两条自检（无需浏览器、无需联网）：
> `python tools/check_js.py` —— 题库数据、语法、资源引用、各功能入口
> `python tools/check_runtime.py` —— quickjs + 假 DOM 跑「对战 → 捕捉」全流程
>
> 另有一条**浏览器首帧守卫**（需要本机 Chrome 开调试端口，改过扉页/动画后必跑）：
> `python tools/check_flyleaf_fan.py [URL]` —— 逐帧记录扉页 14 张牌的横向跨度，
> 要求首帧就已在扇位、全程没有任何「叠成两摞」的帧。它防的是这样一类事故：
> 卡片先插入、后写位置、中间读了一次布局，浏览器便会先按塌叠状态画一帧，
> 再用过渡摊开——机器慢或显卡弱时这一帧会被卡住，一进站就像牌堆塌了。

### 方式三：部署到自己的服务器

1. 复制环境变量模板并填写：`cp .env.example .env`
2. 上传站点文件到服务器目录（默认 `/opt/relic`）
3. 使用仓库内的 nginx 配置（已含 gzip、缓存策略与安全响应头）：
   ```bash
   cp tools/nginx-relic.conf /etc/nginx/sites-available/relic
   ln -sf /etc/nginx/sites-available/relic /etc/nginx/sites-enabled/relic
   nginx -t && systemctl reload nginx
   ```
4. 若需在本机跑 AI 转发服务：`python server.py` 后用 nginx 把 `/api/` 反代到 `127.0.0.1:8000`
5. 一键推送改动（口令只走环境变量，不写进代码）：
   ```bash
   export SSH_HOST=你的服务器IP SSH_USER=root SSH_PASS=你的口令
   python tools/_push_files.py js/app.js css/style.css index.html
   ```

详细步骤见 [`部署到服务器.md`](部署到服务器.md) 与 [`docs/环境变量与安全.md`](docs/环境变量与安全.md)。

### 关于 AI 能力

- **开箱即用**：站点内置云端中转，登录后即可直接使用 AI，无需配置任何密钥。
- **自备密钥（可选）**：在页面「🔑 接入 AI 大模型」里填写自己的 Key，
  Key 只保存在**本机浏览器 localStorage**，不会上传到任何服务器，也不会进入仓库。
- **环境变量**：本项目**不使用**服务端密钥；`.env.example` 中的 `ZHIPU_API_KEY` 等
  仅供需要自建转发服务时参考。

## 四、代码规范

- **注释**：每个文件头部有「职责说明」块；每个业务函数前有一行中文注释说明用途；
  非直觉的算法（如 canvas 裁切、alpha 包围盒扫描）在行内解释了「为什么这么做」。
- **命名**：页面渲染函数统一 `viewXxx()`，玩法模块统一 `Xxx` 前缀文件名（`aw-*.js`），
  手机端专属逻辑集中在 `css/mobile.css` 与 `js/mobile-nav.js`。
- **桌面/手机隔离**：手机样式一律写在 `@media (max-width:860px)` 内，
  禁止在通用样式里改桌面版式；新增手机交互优先用渐进增强，脚本失效时自动降级。
- **资源版本**：修改 `js/*.js`、`css/*.css` 后同步提升入口页的 `?v=` 号，避免缓存不生效。
- **安全**：口令只以加盐哈希形式出现，服务器地址与 SSH 口令只从环境变量读取，
  调试脚本与素材存档不入库（见 `.gitignore`）。

## 五、落地与商业化

> **说明**：本作品是高校学生团队的参赛原型，**目前没有签约客户**。下面的价格与规模是按公开资料和同类项目推算的**参考区间**，不是合同报价；三条路径都对照现有代码能力做过可行性核对，真正落地前需与馆方、学校另行确认。
>
> 站内对应页面：顶部导航「探索 → 🤝 落地与合作」（`#/biz`），内容与本页一致。

### 5.1 三条路径

| 路径 | 客户 | 交付物 | 参考定价 | 起步方式 |
| --- | --- | --- | --- | --- |
| **G 端** · 地方馆与文旅数字化 | 市县级博物馆、文旅局、考古遗址公园 | 精灵化导览（74 件文物 + 语音讲解）、12 站打卡动线、馆方后台知识库 | 8–15 万元 / 馆 / 年（含首年内容建设） | 先做 1 家共建样板馆，用一个学期把内容换成本馆馆藏 |
| **B 端** · 研学与课后服务 | 研学机构、中小学课后服务、少年宫 | 按校订阅、教师端任务单、学生作品（赋彩 / 打卡海报 / 心仪卡） | 3–6 万元 / 校 / 年 | 找 1 所合作校做社团课试点，跑完一个学期再谈年框 |
| **能力授权** · 馆方 API | 有数字化预算的馆、第三方导览 App、文博内容平台 | RAG 知识库 + 精灵人格 + Agent 工具链，按协议接入 | 基础授权费 + 调用阶梯 | 先开放 1 个馆的问答能力做联调，按调用量结算 |

三条路径的差异在于**交付形态**：G 端是项目制、B 端是订阅制（边际成本接近 0、最容易起量）、能力授权是一次建设多处复用（长期毛利最高）。

### 5.2 成本结构：哪几件事不花钱

一次问答经过四个环节，其中三个在自建侧完成，只有最后一个按量付费：

| 环节 | 位置 | 成本 |
| --- | --- | --- |
| 双路检索与融合（BM25 + LSA → RRF） | 自建服务 | **0 元**，实测平均 0.71 ms |
| 安全过滤与 PII 脱敏 | 本地规则 | **0 元**，不调外部接口 |
| 语音合成 | 本地缓存 | 同一精灵、同一句话命中缓存即 **0 元** |
| 模型生成 | 云端 | 唯一按量付费项；快慢级联让简单问题走轻档 |

由此得到两个可对馆方交代的结论：

1. **账单只随「生成」增长**，不随检索量和用户数增长 —— 用户越多，检索成本并不跟着涨。
2. **研学场景成本会被摊薄** —— 同一批学生会反复问同类问题，缓存与级联命中率高。

站内「AI 评测台」（`#/eval`）可当场重跑延迟与命中率，不是纸面数字。

| 阶段 | 目标 |
| --- | --- |
| 第 1–4 月 | **样板共建**：1 家馆 + 1 所学校，把内容换成对方馆藏，跑通第一篇交付文档 |
| 第 5–8 月 | **区域复制**：沿河北 12 站动线铺开，把部署、内容替换、教师培训沉淀成标准包 |
| 第 9–12 月 | **能力授权**：开放馆方 API 与第三方导览合作，IP 二次开发按比例分成 |

### 5.4 边界与合规

- 文物图像版权归各馆藏机构，本站只做 Q 版二创与档案整理，**商用前须逐件取得授权**。
- 研学场景涉及未成年人：不采集人脸、不做用户画像、除对话外不留身份信息。
- AI 输出保留引用来源，涉年代、尺寸、出土信息以馆方公示为准，不作权威结论。
- 开源仓库只放代码与脱敏后的公开资料，密钥与馆方内部数据一律不入库。
