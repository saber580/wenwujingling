# 环境变量与安全说明

## 一、环境变量

项目**本身不需要任何环境变量即可运行**（纯静态站点）。下面这些只在特定场景用到：

| 变量 | 用途 | 是否必须 | 备注 |
| --- | --- | --- | --- |
| `DEMO_EMAIL` | 演示账号邮箱 | 否 | 仅用于本地服务启动时在控制台提示 |
| `DEMO_PASS` | 演示账号口令 | 否 | **只放环境变量**，源码与文档一律不写明文 |
| `ZHIPU_API_KEY` / `ARK_API_KEY` | 自建 AI 转发时的密钥 | 否 | 普通用户无需配置；页面内填 Key 只存本机 localStorage |
| `IDENT_BRIDGE_HOST` / `IDENT_BRIDGE_PORT` | 本机 AI 小桥监听地址 | 否 | 默认 `127.0.0.1:8898`，只本机可用 |
| `SSH_HOST` / `SSH_USER` / `SSH_PASS` | 一键部署到服务器 | 否 | 口令只从环境变量读取，脚本内不写死 |
| `REMOTE_DIR` | 服务器站点目录 | 否 | 默认 `/opt/relic` |
| `PORT` | 本地预览端口 | 否 | 默认 8000 |

用法：

```bash
cp .env.example .env      # .env 已在 .gitignore 中，不会入库
# 编辑 .env 填写自己的值
```

## 三、nginx 安全响应头

`tools/nginx-relic.conf` 中已加入：

```nginx
add_header X-Content-Type-Options "nosniff" always;
add_header X-Frame-Options "SAMEORIGIN" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
add_header Permissions-Policy "geolocation=(), microphone=(), camera=()" always;
```

> 注意 nginx 的 `add_header` 是**就近覆盖**：某个 `location` 里只要写了任意 `add_header`，
> server 级的安全头就会全部失效。因此每个设置了 `Cache-Control` 的 `location` 内
> 都重复声明了一遍，改配置时请保持这个习惯。

## 四、已知限制（按需自行加强）

1. **登录为演示级校验**：哈希写在前端 JS 中，任何人可绕过前端直接改本地状态。
   正式使用请改为服务端校验（签发短期 token、接口鉴权）。
2. **建议开启 HTTPS**：默认配置为 HTTP 明文，申请证书后把 `listen 80` 改为 443 并跳转。
3. **口令强度**：演示口令请自行设置为高强度口令，并替换哈希值。

## 五、发现漏洞怎么办

请通过仓库 Issue 反馈，或直接联系团队。请勿在 Issue 中粘贴真实密钥、服务器口令等敏感信息。
