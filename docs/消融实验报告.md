## 一、方法
每一组消融只关闭一个（或一组）特性，其余保持不变，逐题重跑。检索指标由 Python 侧真跑 `mcp/hybrid_rag.py`，安全与提示词指标由 Node 侧真跑页面在用的 `js/safety.js` 与 `js/prompt-registry.generated.js`，避免出现「评测用的是另一套规则」的情况。
- **hit@3 / MRR**：top3 是否命中含期望词的档案片段，以及首个相关片段的排名倒数
- **双路命中**：BM25 与 LSA 两路同时命中的片段数，衡量语义路是否真的补到了东西
- **引用覆盖 / 悬空残留**：角标能否追回到档案；过滤关闭后有多少悬空角标漏进最终回答
- **拦截命中 / 误伤**：注入与越权题是否被挡，正常题是否被错挡
- **并行批次 / 耗时**：三个互不依赖的检索调用并发执行与逐个执行的实测耗时（走真实 HTTP 打 MCP server，包含网络等待）

## 三、逐项归因
| 关掉的特性 | 直接后果 | 本次实测 |
|---|---|---|
| 双路召回 | 语义改写类问题失去 LSA 通道，只剩字面匹配 | MRR 0.939 → 0.909；双路命中 3.00 → 0.00 |
| 引用角标 | 回答不再标明依据，无法溯源 | 引用覆盖 1.000 → 0.000 |
| 内容过滤 | 注入/越权直接放行，PII 不脱敏，悬空引用与无依据数字漏出 | 拦截 2/2 → 0/2；悬空残留 0 → 14 |
| 显式规划 | 不再产出 goal/steps/tools，工具选择完全靠模型临场判断 | 平均计划步数 1.64 → 0 |
| 反思阶段 | 资料不足时不再定向补查 | 补查次数 1 → 0 |
| 并行调用 | 多个独立工具退回逐个等待 | 并行批次 1 → 0；三个调用串行 31.72 ms、并行 4.89 ms（远程 MCP） |
| 全部关闭（基线） | 退化为最初单路检索 + 无安全层 | hit@3 0.909、MRR 0.909、拦截 0/2 |

## 四、结论
1. **双路召回有独立贡献**：语义改写题（如「汉代人怎么让屋子不被烟熏黑」）在只留 BM25 时排名明显后退，说明 LSA 通道补到的是字面之外的关联，不是重复计数。
2. **引用溯源与安全过滤是同一条链**：关掉角标，覆盖率为 0；关掉过滤，14 处悬空引用与 14 处无依据硬数字直接进入回答。两者共同保证「说的每句有出处」。
3. **规划 / 并行 / 反思改变的是过程可解释性与耗时**，不直接改变离线召回分数；它们的价值体现在可展示的阶段轨迹与出错时的自我修正，需结合线上问答轨迹评估。
4. 安全层在全部 14 道正常题上误伤为 0，说明规则收得比较窄，没有把「革命文物」「兵器」这类正当馆藏词误判。
