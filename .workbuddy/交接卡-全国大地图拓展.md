## 五、关键技术约定（务必遵守）

1. **校验硬性要求**（tools/check_js.py，每个精灵必须有）：
   - history 含「出土/发掘/发现/原址/来历」
   - knowledge 含「出土/来历」问答（keys 含出土/挖掘/挖出/考古/来历）
   - quiz ≥ 5 题（含出土题 + 尺寸体量题）
   - comic ≥ 3 幕
2. **立绘路径**：分站精灵放 `精灵/<站点>/<id>.webp`，通用精灵（无 dir）放 `精灵/<id>.webp`；透明立绘放 `精灵/透明/<id>.webp`
3. **数据分文件**：基础字段在 data.js，详细字段（comic/knowledge/quiz/history）在 data-deep.js 的 SPIRIT_DEEP，由 data-lazy.js 合并
4. **版权**：不能挪用"物华弥新"等商业游戏的版权素材，背景图/立绘都用 ImageGen 原创生成（生成图自带水印，用 PIL 去右下角水印）
5. **主线剧情引擎（新架构，2026-11-09 重写）**：
   - 站点剧本数组 `VN_ST_1..VN_ST_4`，每站结构：
     `{ id:站点id, p:节点前缀, hub:{t,sp,lines}, caps:[{t,sp,pick,lines}×3], win:{t,sp,lines} }`
   - `VN_MAIN` 由构链函数自动生成（hub → 3×cap → win → 下一站 hub），**不要手写 next/choices**，加站只需往 `VN_ST_4` 后面 push 一个对象
   - 节点运行态字段：id / station / kind(hub|capture|win|end) / title / speaker / lines / choices / next / x,y
   - 台词行：`{t:"narr"|"say", id:精灵id, x:"正文"}`；标题统一用 `「地点 · 物件」` 格式（流程图靠 ` · ` 拆两行显示）
   - 结局 id 约定 `<前缀>_e1..e3`，记录在 cap 的 choices[0].ending
